Perfil y resultado

Primero entender; después configurar y construir.

¿Para quién es?

Freelancers, emprendedores y profesionales que quieren crear una página de servicios con IA. Se empieza explicando las herramientas y su relación.

Nivel de entrada

Principiante. Manejo básico del computador, archivos y navegador. No se requiere experiencia previa programando ni tener WordPress instalado.

Al finalizar, el alumno podrá

  1. Explicar qué hacen Codex, GitHub, Hostinger, WordPress y Elementor dentro del proyecto.
  2. Crear un WordPress de práctica en Hostinger y preparar una página con Elementor.
  3. Dirigir a Codex para crear un bloque que reúna HTML, CSS y JavaScript en el mismo archivo.
  4. Guardar versiones en GitHub, pegar el bloque en Elementor y comprobar la página publicada.
  5. Corregir, actualizar y recuperar el código mediante un proceso sencillo y documentado.

Qué necesita el alumno antes de comenzar

  • Computador con internet, navegador actualizado y acceso a Codex mediante una aplicación compatible.
  • Cuenta de GitHub y GitHub Desktop instalado. Se enseñan el repositorio, la conexión de la carpeta y el guardado de versiones.
  • Acceso a una cuenta de Hostinger con alojamiento activo compatible con WordPress. La instalación de WordPress y la preparación de Elementor se enseñan en el módulo 2.
  • Una dirección de práctica disponible; se puede utilizar la opción temporal del proveedor. Textos e imágenes del kit de ejemplo o del propio negocio.

Las cuentas, el alojamiento y las licencias que correspondan se preparan antes de grabar o practicar. Sus costos no están incluidos. No es obligatorio comprar un dominio para seguir la demostración en una dirección temporal.

Un único bloque de código

HTML: contenido y estructura. CSS: diseño dentro de <style>. JavaScript: interacciones dentro de <script>. Las tres partes se conservan juntas y se pegan en un mismo widget HTML de Elementor.

Proyecto: una landing de servicios con presentación, beneficios, preguntas frecuentes y contacto. GitHub guarda el código; WordPress lo publica en Hostinger. Las imágenes se alojan como recursos del sitio.

Programa detallado · Módulo 1 de 6

01

Fundamentos: entiende cada herramienta

40 min

Objetivo: Comprender qué hace cada herramienta y cómo HTML, CSS y JavaScript forman un único bloque para la página.

1.1

Qué es Codex y cómo te ayuda a crear una web

10 min

Qué se enseñará. Se explicará qué es un asistente de programación y cómo Codex transforma instrucciones en código. Se presentarán sus usos en el curso: crear una sección, cambiar su diseño, corregir un fallo y explicar un archivo. El alumno entenderá que debe definir el objetivo y revisar el resultado antes de publicarlo.

Demostración en pantalla. El docente mostrará una petición sencilla, el código generado y su resultado visual, señalando qué decidió la persona y qué produjo Codex.

Al terminar. Reconocer para qué utilizar Codex y cómo dirigir su trabajo con instrucciones concretas.

1.2

Qué son Git y GitHub y por qué guardar versiones

10 min

Qué se enseñará. Se explicará Git como sistema que registra cambios y GitHub como plataforma donde conservar el repositorio. Se introducirán los términos archivo, carpeta, repositorio, copia local y commit con un ejemplo. Se aclarará que el historial del código permite recuperar versiones, mientras que WordPress necesita además su propia copia de seguridad.

Demostración en pantalla. Se compararán dos versiones de una misma sección y se localizará el cambio en un historial de ejemplo.

Al terminar. Entender por qué se guarda cada avance y qué se podrá recuperar desde el repositorio.

1.3

Hostinger, dominio, WordPress y Elementor: qué hace cada uno

10 min

Qué se enseñará. Se distinguirán el hosting, que aloja el sitio, y el dominio, que permite localizarlo. Se explicará Hostinger como proveedor y hPanel como su panel de gestión; WordPress como sistema para administrar la web; y Elementor como editor que se instala dentro de WordPress. Se presentará la relación entre estas piezas.

Demostración en pantalla. El docente recorrerá un esquema del sistema y señalará en pantalla el panel del alojamiento, el de WordPress y el editor de Elementor.

Al terminar. Identificar dónde se administra el alojamiento, dónde se gestiona la web y dónde se coloca el código.

1.4

HTML, CSS y JavaScript: tres funciones, un mismo código

10 min

Qué se enseñará. Se explicará HTML como estructura y contenido, CSS como diseño y distribución, y JavaScript como comportamiento e interacción. Los tres se mostrarán dentro del mismo bloque: estilos en una etiqueta style, contenido HTML y lógica en una etiqueta script. Ese será el formato de trabajo que después se pegará en Elementor.

Demostración en pantalla. Se abrirá un único archivo con una tarjeta interactiva y se cambiarán su texto, su color y su comportamiento, identificando cada parte.

Al terminar. Comprender la función de cada lenguaje y reconocerlos integrados en un mismo archivo. Aquí se utiliza JavaScript.

Ejercicio del módulo: Identificar en el ejemplo dónde están HTML, CSS y JavaScript, y explicar el recorrido desde la petición a Codex hasta la publicación en WordPress alojado en Hostinger.

Cómo comprobar el aprendizaje: El alumno distingue las funciones de las herramientas y entiende que entregará un único bloque con contenido, estilos e interacciones.

Práctica independiente del alumno; adicional al tiempo de video.

Programa detallado · Módulo 2 de 6

02

Prepara WordPress en Hostinger

40 min

Objetivo: Crear un WordPress de práctica en Hostinger, reconocer su panel y preparar Elementor para recibir el código.

2.1

Prepara el alojamiento y la dirección de práctica

10 min

Qué se enseñará. Se enseñará a localizar un plan de alojamiento activo compatible con WordPress dentro de hPanel y el espacio donde se creará el sitio. Se explicará qué datos conviene tener listos y cómo elegir una dirección disponible para practicar. Se usará un dominio temporal cuando corresponda para evitar depender de la conexión de un dominio externo.

Demostración en pantalla. El docente accederá a hPanel, ubicará su alojamiento y mostrará las opciones de dirección para el sitio nuevo, sin completar compras durante la clase.

Al terminar. Reconocer los accesos necesarios y definir dónde se instalará el WordPress de práctica.

2.2

Instala WordPress y entra a su administración

12 min

Qué se enseñará. Se demostrará el asistente de instalación de WordPress en Hostinger: selección del sitio, datos de administración y dirección de práctica. Se elegirá una instalación inicial sencilla. Después se accederá al panel de WordPress y se explicará la diferencia entre visitar la página pública y entrar como administrador.

Demostración en pantalla. El docente completará la instalación en su cuenta de práctica, abrirá el panel de WordPress y comprobará que la dirección elegida carga.

Al terminar. Tener una instalación accesible y saber volver tanto al panel de administración como al sitio público.

2.3

Conoce WordPress e instala Elementor

10 min

Qué se enseñará. Se explicará para qué sirven las secciones Páginas, Medios, Apariencia y Plugins. Se distinguirá un tema, que define una base visual del sitio, de un plugin, que añade funciones. Se instalará y activará Elementor, mostrando dónde se abre el editor y cómo localizar el widget HTML que se utilizará después.

Demostración en pantalla. Se recorrerán las áreas esenciales de WordPress, se activará Elementor y se abrirá una página vacía para identificar sus controles.

Al terminar. Ubicar contenidos y recursos e identificar el editor y el widget donde se insertará el bloque completo.

2.4

Crea la página de pruebas y prepara una copia

8 min

Qué se enseñará. Se creará una página en borrador y se elegirá una plantilla que encaje con el diseño previsto. Se explicará cómo conservar o retirar cabecera y pie del tema para evitar duplicarlos. También se localizará la opción de copia de seguridad disponible en el entorno y qué debe conservarse antes de modificar el sitio.

Demostración en pantalla. El docente dejará la página de práctica lista, comprobará su vista previa y mostrará cómo identificar una copia recuperable del sitio.

Al terminar. Disponer del espacio de pruebas y saber qué revisar antes de insertar o sustituir código.

Ejercicio del módulo: Crear el sitio de práctica siguiendo la instalación guiada, entrar a WordPress, activar Elementor y dejar una página en borrador preparada para el proyecto.

Cómo comprobar el aprendizaje: El alumno accede al sitio y a su administración, encuentra el widget HTML y reconoce cómo disponer de una copia antes de hacer cambios.

Práctica independiente del alumno; adicional al tiempo de video.

Programa detallado · Módulo 3 de 6

03

Configura Codex y conéctalo con GitHub

35 min

Objetivo: Preparar el proyecto local, relacionarlo con un repositorio y guardar una primera versión del bloque de código.

3.1

Accede a Codex y prueba tu carpeta de trabajo

8 min

Qué se enseñará. Se mostrará cómo acceder a Codex desde la aplicación elegida para el curso, iniciar sesión y seleccionar una carpeta. Se explicará qué significa dar acceso a los archivos y revisar las acciones propuestas. El alumno hará una primera petición pequeña para verificar que el asistente trabaja en el lugar correcto.

Demostración en pantalla. El docente abrirá una carpeta de prueba, solicitará un archivo HTML sencillo y comprobará que existe en la ubicación seleccionada.

Al terminar. Iniciar una tarea en Codex y encontrar el archivo que genera.

3.2

Crea el repositorio de GitHub y clónalo

10 min

Qué se enseñará. Se creará un repositorio con un nombre reconocible y una visibilidad elegida conscientemente. Se iniciará sesión en GitHub Desktop y se clonará, obteniendo una copia local. Se explicará cómo distinguir la ubicación del computador de la dirección remota de GitHub y comprobar que ambas corresponden al mismo proyecto.

Demostración en pantalla. El docente creará y clonará el repositorio, y localizará su carpeta desde GitHub Desktop y desde el explorador de archivos.

Al terminar. Tener una carpeta local relacionada con un repositorio remoto donde guardar los avances.

3.3

Abre el repositorio en Codex y define el formato

9 min

Qué se enseñará. Se abrirá en Codex la carpeta clonada y se trasladará allí el archivo de práctica. Se creará un AGENTS.md breve con las reglas del proyecto: entregar un único bloque con HTML, CSS y JavaScript integrados, usar estilos propios y conservar las partes que funcionan. Se distinguirán el archivo de código, el brief y las imágenes de apoyo.

Demostración en pantalla. Se escribirá la regla de formato y se pedirá a Codex que revise el archivo sin separar los estilos ni la lógica en archivos adicionales.

Al terminar. Trabajar con Codex sobre el repositorio correcto y mantener el formato de código acordado.

3.4

Revisa, guarda y sincroniza tu primera versión

8 min

Qué se enseñará. Se practicará el ciclo cambiar, revisar, guardar un commit y sincronizar con GitHub. Se leerá una comparación sencilla para saber qué se añadió o eliminó y se escribirá un mensaje que describa el cambio. Se comprobará que guardar el archivo en el computador y enviarlo a GitHub son pasos diferentes.

Demostración en pantalla. Se cambiará un título con Codex, se revisará en GitHub Desktop y se confirmará la nueva versión desde GitHub.

Al terminar. Conservar un avance identificable y verificar que también está guardado en el repositorio remoto.

Ejercicio del módulo: Clonar el repositorio, abrirlo en Codex, definir la regla de código integrado y guardar un primer cambio en el archivo HTML mediante un commit sincronizado.

Cómo comprobar el aprendizaje: La copia local y GitHub contienen el cambio, y el archivo conserva su contenido, sus estilos y su lógica juntos.

Práctica independiente del alumno; adicional al tiempo de video.

04

Diseña y construye tu página en un solo código

55 min

Objetivo: Crear una landing de servicios con ayuda de Codex, integrando contenido, diseño e interacciones desde el primer bloque.

4.1

Define el brief, el diseño y la instrucción para Codex

10 min

Qué se enseñará. Se completará una ficha breve con público, servicio, objetivo, textos, secciones y acción principal. Se elegirá una referencia de colores y distribución. Con esa información se redactará un prompt que indique el resultado esperado, el comportamiento móvil y la entrega en un bloque para Elementor con HTML, CSS y JavaScript integrados.

Demostración en pantalla. El docente usará una plantilla para redactar el brief de un negocio de servicios y convertirlo en una petición concreta de construcción.

Al terminar. Pedir una página con contenido, referencia visual y formato de entrega definidos.

4.2

Genera la cabecera y el bloque principal

15 min

Qué se enseñará. Se construirá la presentación inicial de la página con título, descripción, imagen y botón. Se localizará el HTML del contenido y el CSS incluido en el mismo archivo, junto con el espacio para el JavaScript cuando se necesite. Se abrirá una vista previa y se solicitará un ajuste concreto de diseño.

Demostración en pantalla. El docente generará el primer bloque, revisará el resultado en el navegador y corregirá un espacio o tamaño sin rehacer toda la sección.

Al terminar. Obtener una primera sección revisada que ya utiliza el formato integrado del proyecto.

4.3

Completa servicios, preguntas frecuentes y contacto

15 min

Qué se enseñará. Se añadirán beneficios y servicios conservando los estilos establecidos. Después se incorporarán enlaces internos, preguntas desplegables y un botón de contacto. Se mostrará cómo el JavaScript del mismo bloque aporta comportamiento a los elementos HTML y cómo el CSS mantiene una apariencia coherente. El contacto será un enlace funcional.

Demostración en pantalla. El docente ampliará el bloque existente y comprobará los enlaces y la apertura de las preguntas con ratón y teclado.

Al terminar. Completar la landing manteniendo contenido, estilos e interacciones en un único código reutilizable.

4.4

Ajusta móvil y revisa el bloque para Elementor

15 min

Qué se enseñará. Se revisará el diseño en escritorio, tablet y móvil para corregir columnas, imágenes y desbordamientos. Se limitarán los estilos a un contenedor propio. Se distinguirá el bloque para Elementor del documento de vista previa, evitando copiar etiquetas generales como html, head o body dentro del widget. HTML, style y script permanecerán juntos.

Demostración en pantalla. Se corregirá un problema móvil y se guardará la versión final del bloque, comprobando su formato y las rutas de los recursos.

Al terminar. Tener una página adaptable y un único bloque claramente identificado para pegar en Elementor.

Ejercicio del módulo: Completar la landing del negocio de ejemplo, corregir su adaptación móvil y guardar el archivo del bloque listo para Elementor en el repositorio.

Cómo comprobar el aprendizaje: El código contiene HTML, CSS y JavaScript integrados; los enlaces y la interacción funcionan y la página se visualiza en tres tamaños de pantalla.

Práctica independiente del alumno; adicional al tiempo de video.

Programa detallado · Módulo 5 de 6

05

Integra y publica tu página en WordPress

45 min

Objetivo: Insertar el bloque completo en Elementor, ajustar sus recursos y validar la página publicada en el sitio de Hostinger.

5.1

Pega el código completo en el widget HTML

12 min

Qué se enseñará. Se retomará la página preparada en el módulo 2 y se insertará un widget HTML. Se copiará el bloque completo, incluidos el contenido, style y script. Se explicará cómo reconocer el inicio y el final del código y cómo comprobar que no falta ninguna parte al trasladarlo desde el archivo hacia Elementor.

Demostración en pantalla. El docente copiará el bloque completo, lo pegará en un único widget y abrirá la vista previa del borrador.

Al terminar. Trasladar el diseño y sus interacciones a Elementor en una sola inserción de código.

5.2

Prepara imágenes, enlaces y recursos del sitio

13 min

Qué se enseñará. Se subirán las imágenes del proyecto a la biblioteca de medios y se reemplazarán las rutas del computador por sus URLs de WordPress. Se revisarán enlaces internos y destino de contacto. Se explicará que unificar HTML, CSS y JavaScript no significa incrustar todos los archivos multimedia dentro del código.

Demostración en pantalla. El docente corregirá una imagen que depende de la carpeta local y probará nuevamente la navegación y el contacto desde la página.

Al terminar. Conseguir que los recursos carguen desde el sitio y que el bloque no dependa del computador de trabajo.

5.3

Resuelve diferencias de diseño e integración

10 min

Qué se enseñará. Se identificarán diferencias entre la vista previa y WordPress debidas a anchos, espacios del editor, estilos del tema o caché. Se enseñará a revisar una causa a la vez y pedir a Codex una corrección limitada al contenedor del bloque. Se probará de nuevo el conjunto tras sustituir el código.

Demostración en pantalla. El docente corregirá un ancho o espaciado que cambió dentro de Elementor y comparará el resultado en escritorio y móvil.

Al terminar. Ajustar el bloque dentro de WordPress sin extender sus cambios a otras partes del sitio.

5.4

Publica y comprueba la experiencia del visitante

10 min

Qué se enseñará. Se revisarán título, dirección de la página y visualización antes de publicar. Después se abrirá la URL real sin sesión de administración para comprobar recursos, navegación, interacción y contacto. Se recordará que la dirección de práctica debe estar disponible y que guardar una versión en GitHub no publica automáticamente el widget.

Demostración en pantalla. El docente publicará en el sitio de práctica, lo abrirá en una ventana privada y recorrerá sus acciones principales.

Al terminar. Publicar la landing y comprobar que funciona para un visitante desde su URL.

Ejercicio del módulo: Pegar el bloque en Elementor, corregir las rutas de recursos y publicar en el WordPress de práctica creado en Hostinger. Guardar capturas de escritorio y móvil.

Cómo comprobar el aprendizaje: La URL carga sin sesión, las imágenes se muestran y funcionan la navegación, el contacto y la interacción del bloque.

Práctica independiente del alumno; adicional al tiempo de video.

06

Corrige, actualiza y conserva tu trabajo

25 min

Objetivo: Aplicar una revisión básica y mantener el bloque publicado con apoyo de Codex y el historial de GitHub.

6.1

Revisa calidad visual, accesibilidad y estructura básica

7 min

Qué se enseñará. Se aplicará una lista breve de comprobación: lectura del contenido, orden de encabezados, descripción de imágenes, contraste y acceso con teclado. Se revisará también el tamaño de los recursos. El alumno identificará una mejora concreta que pueda resolverse en el bloque sin cambiar el diseño general del sitio.

Demostración en pantalla. El docente detectará y corregirá una incidencia, como una imagen sin descripción o un título con una jerarquía inadecuada.

Al terminar. Revisar la calidad básica de la página y documentar una corrección comprobable.

6.2

Describe un fallo y corrígelo con Codex

7 min

Qué se enseñará. Se enseñará a comunicar qué debería pasar, qué pasa realmente y cómo reproducir el problema. Se utilizará una captura o un mensaje de error cuando aporte información. Se pedirá una corrección puntual que conserve el bloque integrado y se revisará el cambio antes de llevarlo otra vez a WordPress.

Demostración en pantalla. El docente resolverá un enlace o una interacción defectuosa y repetirá los pasos que antes provocaban el fallo.

Al terminar. Pedir ayuda con evidencia y verificar que la solución funciona.

6.3

Guarda una mejora y recupera el bloque anterior

6 min

Qué se enseñará. Se repasará el ciclo de edición local, vista previa, commit, sincronización y actualización del widget. Se mostrará cómo recuperar el contenido de una versión anterior y guardarlo como un nuevo cambio. Se aclarará que recuperar el archivo en GitHub no sustituye por sí solo el código que está publicado en Elementor.

Demostración en pantalla. El docente guardará una mejora sencilla y recuperará el bloque anterior, comprobando la versión del archivo y la página.

Al terminar. Actualizar o recuperar el bloque sin perder la trazabilidad del proyecto.

6.4

Entrega tu proyecto y repite el proceso

5 min

Qué se enseñará. Se organizará la entrega con URL, bloque final, historial y README con las instrucciones de actualización. Se explicará cómo iniciar otra página a partir del mismo procedimiento cambiando brief, contenido e identidad visual. Se revisará que no queden enlaces ni datos de ejemplo ajenos al nuevo negocio.

Demostración en pantalla. El docente recorrerá la entrega e identificará qué archivo se copia en Elementor y cómo localizar su versión más reciente.

Al terminar. Presentar un proyecto comprensible y repetir el proceso de creación con una nueva página.

Ejercicio del módulo: Revisar la página, resolver una incidencia y conservar una versión final del bloque. Entregar la URL, el repositorio y una guía breve de actualización y recuperación.

Cómo comprobar el aprendizaje: El archivo final coincide con el bloque publicado y otra persona puede entender cómo se construyó y cómo se actualiza.

Metodología y entrega

Aprender construyendo una misma página.

Cada módulo añade una parte al proyecto anterior. El alumno observa el proceso, replica el paso y conserva una evidencia de su avance.

Dentro de los 240 minutos

Fundamentos al inicio, configuración guiada, construcción y publicación. Cada lección combina explicación y demostración. Las esperas de instalación se editan en el video.

Práctica independiente

Estimación orientativa: 4 a 6 horas adicionales para repetir los pasos, personalizar el proyecto y completar la entrega. Varía según la experiencia del alumno.

Materiales de apoyo propuestos

Recursos a preparar por el docente para acompañar la grabación; no son materiales ya producidos con esta propuesta.

  • Plantilla de brief: ficha para definir público, oferta, objetivo, secciones y referencias antes de pedir código.
  • Banco de prompts: ejemplos comentados para planificar, construir, adaptar a móvil, corregir errores y revisar el resultado.
  • Repositorio de práctica: archivo de código integrado, versiones por módulo y bloque final; README con pasos de instalación, uso y actualización.
  • Kit visual del proyecto: textos e imágenes de ejemplo para seguir la demostración aunque el alumno no tenga una marca propia.
  • Guía de publicación y mantenimiento: pasos para preparar WordPress en Hostinger, comprobar la página y actualizar o recuperar el bloque integrado.

Entrega y evaluación sugeridas

El alumno entrega la URL de su página de práctica, acceso de revisión al repositorio y capturas de escritorio y móvil. No comparte credenciales.

Decisiones que hacen viable el recorrido

  • Fundamentos antes de ejecutar: se explica cada herramienta y el papel de HTML, CSS y JavaScript. Después se prepara WordPress y se configura el trabajo de Codex con GitHub.
  • Instalación guiada en Hostinger: cuenta y alojamiento activos antes de la clase. Se crea un sitio nuevo de práctica con una dirección disponible, usando la opción temporal cuando corresponda.
  • Un mismo código durante todo el proyecto: HTML, CSS en style y JavaScript en script permanecen juntos en el bloque para Elementor. Los recursos multimedia se alojan en WordPress.
  • Un proyecto acotado: una landing de servicios, con una interacción sencilla. Se revisa antes de publicar y se conserva el historial del bloque y una copia del sitio.

Límites de estas cuatro horas

Incluye la instalación básica de WordPress y Elementor. Quedan fuera las compras en directo, las migraciones, la resolución avanzada de DNS, la administración de servidores, el desarrollo de plugins, WooCommerce, formularios con backend y automatizaciones con GHL o n8n. La práctica y las esperas del alumno son adicionales.

Preparación de la grabación

  1. Confirmar con Daxus público, formato de video y acceso de los alumnos a las herramientas.
  2. Disponer de una cuenta de Hostinger de demostración y un sitio vacío; preparar el ejemplo integrado y los recursos visuales.
  3. Grabar una lección piloto y validar el ritmo. Registrar los 24 videos con versiones del código por módulo.
  4. Comprobar la instalación, la publicación y la recuperación del bloque; revisar el kit y las instrucciones de entrega.

El bloque integrado permite enseñar las funciones de los tres lenguajes sin repartir el código de la página en archivos CSS y JavaScript separados. Los textos del brief y la documentación del repositorio se conservan como apoyo.
